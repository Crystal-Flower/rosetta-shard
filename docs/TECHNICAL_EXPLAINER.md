# Technical Explainer: How Rosetta Shard Works (In Plain Terms)

> **"Edge memory that survives AI model upgrades, queries cloud indexes built with different embedding models, and tells you, with a statistical guarantee, when it can be trusted."**

---

## 1. What is Rosetta Shard?

**Rosetta Shard** is a safety, migration, and trust platform for **Edge AI vector memory** built on **[Qdrant Edge](https://qdrant.tech/documentation/edge/)**.

In modern AI deployments, edge devices (smartphones, IoT gateways, disaster-response drones, tactical field tablets, subsea rovers) store searchable knowledge locally as **numerical vectors** (embeddings). This allows devices to perform rapid, private, offline search without relying on continuous internet connectivity.

However, when Central Command / Cloud Base upgrades its embedding model, edge devices are trapped in the past. **Rosetta Shard acts as a mathematical Rosetta Stone for vector memory**, enabling edge devices to upgrade their local stores in milliseconds over a 128 KB bundle—with **zero raw text transmitted** and **statistically certified recall**.

## 2. The Real-World Problem: "Silent Semantic Failure"

### The Hidden Trap in Vector Databases
Vectors are lists of numbers generated by neural networks that capture the semantic meaning of sentences.
For example, a lightweight edge model (**Model A**, 384 dimensions) might encode a safety manual like this:
```text
"Lithium battery thermal degradation rate"  ──►  Model A  ──►  [0.12, -0.45, 0.88, ...] (384 numbers)
```

Later, the cloud upgrades to a state-of-the-art model (**Model B**, 1024 or 384 dimensions):
```text
"Lithium battery thermal degradation rate"  ──►  Model B  ──►  [0.74, 0.02, -0.31, ...] (1024 numbers)
```

This creates three critical engineering bottlenecks:

1. **Dimension Incompatibility:** You cannot compute a dot product between a 384-d vector and a 1024-d vector.
2. **Silent Semantic Collapse:** Even if both models share the exact same dimensionality (e.g. swapping `all-MiniLM-L6-v2` for `bge-small-en-v1.5`, both 384-d), their learned coordinate axes are arbitrarily rotated relative to each other.
3. **The Hallucination Trap:** Standard vector databases do **not** raise an exception when searching mismatched spaces. They compute cosine similarity on scrambled coordinate axes, return **HTTP 200 OK**, and present completely irrelevant documents with a deceptive **0.824 cosine score**. Downstream autonomous agents (autopilots, clinical triage systems) act on corrupted memories without warning.
4. **The Naive Fix Fails:** Re-embedding edge data requires downloading gigabytes of neural network weights over slow connections (e.g. satellite links), draining edge batteries running heavy CPU inference, and requires the **original raw text**—which may have been deleted for privacy or storage efficiency.

## 4. The Four Technical Pillars (Explained Simply)

### 🛡️ Pillar 1: Space Guard (`rosetta/space.py`)
*Passport control for vector databases.*

- **The Problem:** Standard databases do not know which model produced a vector.
- **The Solution:** Space Guard tags every vector collection and query with an explicit coordinate space identifier:
  $$\text{Space ID} = \langle \text{model\_name} \rangle @ \langle \text{revision} \rangle / \langle \text{dimension} \rangle / \langle \text{distance\_metric} \rangle$$
  *(e.g., `bge-small@main/384/l2` vs `bge-large@main/1024/l2`)*.
- **How it works:** If a query's Space ID does not match the target index, Space Guard immediately intercepts the search and halts execution with a `SpaceMismatchError`.
- **Impact:** Eliminates **100% of silent cross-space failures** before corrupted data can reach an autonomous agent.

---

### ⚡ Pillar 2: Compact 128 KB Zero-Text Adapter (`rosetta/adapters/`, `rosetta/bundle.py`)
*A mathematical dictionary connecting two AI models.*

- **The Problem:** Edge devices cannot re-embed their documents using the large model.
- **The Solution:** The cloud trains a closed-form linear mapping $W \in \mathbb{R}^{d_{small} \times d_{large}}$ using **100 generic public anchor sentences**:
  $$W = (X^T X + \lambda I)^{-1} X^T Y$$
  Where:
  - $X$ is the public anchors embedded with the small edge model ($100 \times 384$).
  - $Y$ is the same anchors embedded with the large cloud model ($100 \times 1024$).
  - $\lambda$ is a Tikhonov regularization factor ($\lambda = 0.01$).
- **How it works:** The resulting projection matrix $W$, along with anchor statistics and calibration quantiles, is packed into a **128.5 KB bundle**.
- **Impact:**
  - **Zero Raw Text:** The edge device never transmits its private files to the cloud.
  - **Micro Bandwidth:** 128 KB transmits in **0.12 seconds** over a 9.6 kbps satlink, compared to 31 hours for a 1.34 GB model download.

---

### 🔄 Pillar 3: In-Process Atomic Shard Migration (`rosetta/migrate.py`)
*Upgrading stored edge memory in under one second.*

- **The Problem:** Running neural network inference across thousands of local vectors locks edge CPUs, drains battery, and risks data corruption if interrupted.
- **The Solution:** Instead of re-embedding, Rosetta Shard applies the linear adapter directly to the stored vector coordinates inside Qdrant Edge:
  $$\hat{v}_{new} = \frac{v_{old} \cdot W}{\|v_{old} \cdot W\|_2}$$
- **How it works:** 
  - Streams vectors in batches from the existing Qdrant Edge shard.
  - Multiplies each vector by $W$ via optimized BLAS matrix math.
  - Writes the new vectors to a staging directory and executes an **atomic filesystem swap**.
  - If battery dies or power is lost mid-migration, the original shard remains intact.
- **Impact:**
  - Migrates 2,000 vectors in **0.66 seconds** (compared to 134.7 seconds for full re-embedding).
  - **203× speedup** with minimal CPU cycle and battery consumption.

---

### 📜 Pillar 4: Calibrated Conformal Recall Certificates (`rosetta/certificate.py`)
*A mathematical warranty for retrieval quality.*

- **The Problem:** Raw cosine scores after vector adaptation are uncalibrated and misleading. How does an autonomous robot know if the translated search result is actually trustworthy?
- **The Solution:** Rosetta Shard uses **Split Conformal Prediction** to issue distribution-free statistical guarantees on retrieval overlap.
- **How it works:**
  1. The cloud evaluates the adapter on a held-out calibration set and computes non-conformity residuals:
     $$r_i = 1 - \text{Overlap@}k(q_i)$$
  2. For a user-selected significance level $\alpha$ (e.g., $\alpha = 0.05$ for 95% confidence), it computes the empirical quantile $\hat{q}_\alpha$:
     $$\hat{q}_\alpha = \text{Quantile}\left(\frac{\lceil (n+1)(1-\alpha) \rceil}{n}, \{r_1, \dots, r_n\}\right)$$
  3. At runtime, the edge device extracts lightweight query features (margin gap between top-1 and top-$k$, anchor cosine similarity) and calculates the certified lower bound:
     $$\mathbb{P}(\text{Overlap@}k \ge \tau) \ge 1 - \alpha$$
- **Impact:** The autonomous system acts only when mathematically guaranteed ($P \ge 95\%$). If a query is out-of-distribution or uncertain, it safely escalates to cloud fallback instead of hallucinating.

## 7. Frequently Asked Questions (FAQ)

### Q: Why not just re-embed the edge database when the cloud model updates?
1. **Compute & Battery:** Re-running transformer models on edge hardware (ARM Cortex / Raspberry Pi / mobile NPU) takes minutes to hours, draining battery.
2. **Missing Raw Text:** In many privacy-sensitive applications (healthcare, personal finance, defense), raw user text is discarded immediately after embedding. You cannot re-embed text that no longer exists.
3. **Bandwidth:** Downloading large model weights (1.3+ GB) over constrained edge links (satlink, LoRa, 3G) is impractical.

### Q: Why a linear Ridge Adapter instead of a deep neural network?
A linear adapter ($W \in \mathbb{R}^{384 \times 1024}$):
- Fits in a compact **128 KB** payload.
- Computes in **0.13 ms** via a single matrix multiplication without needing a GPU or PyTorch runtime.
- Has a closed-form analytical solution that cannot suffer from training instability or mode collapse.
- Preserves relative distance topology without hallucinating non-linear artifacts.

### Q: What makes Qdrant Edge central to this architecture?
Qdrant Edge provides a standalone, embedded Rust vector engine that runs directly within low-power edge environments. Rosetta Shard pairs with Qdrant Edge to provide the missing semantic safety and upgrade layer: in-memory payload streaming, atomic disk swaps, and space validation.
